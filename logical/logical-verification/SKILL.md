# logical-verification [결과물_파일경로]

로지컬 씽킹 결과물을 MECE 원칙과 품질 기준으로 검증하여 리포트를 생성한다.

## 옵션
- `--focus me|ce|structure|quality` (기본: 전체)
- `--strict` (엄격 모드)
- `--report detailed|summary` (기본: detailed)

## 검증 5단계

### 1단계: 구조 분석
- 최상위 목표 명확성
- 뎁스별 분해 깊이 적절성
- 브랜치 간 논리적 관계

### 2단계: ME (상호배타성) 검증
```yaml
질문:
  - "각 브랜치가 서로 겹치는가?"
  - "하나의 항목이 여러 브랜치에 속할 수 있는가?"
  - "분해 기준이 형제 브랜치에서 일관되는가?"

위반 표시:
  - (중복id01), (중복id02): 동일 내용
  - 기준 불일치: 분해 기준 혼재 지점

통과 조건:
  - 항목이 2개+ 브랜치에 속하지 않음
  - 브랜치 경계가 명확
  - 동일 분해 기준 일관 적용
```

### 3단계: CE (완전망라성) 검증
```yaml
질문:
  - "모든 경우를 다뤘는가?"
  - "빠진 영역이 있는가?"
  - "새로운 하위 항목 가능성은?"

누락 표시:
  - (누락): 빠진 내용
  - 집합 유형 판단: 닫힌 vs 열린
  - 열린 집합에서 "기타" 브랜치 필요성

통과 조건:
  - 모든 영역 포함
  - 닫힌 집합: 논리적 완전 정의
  - 열린 집합: "기타"로 확장성 보장
```

### 4단계: 품질 기준 평가
```yaml
구조 품질:
  - 동일 기준 원칙 준수
  - 중복 없음
  - 누락 없음
  - 확장성

내용 품질:
  - 상위 목표 기여도
  - 실행 가능성
  - 완료 조건 명확성

실용성:
  - 팀 이해도
  - 관리 용이성
  - 구조 유지성
```

### 5단계: 원자적 Task 검증
- 1-3일 완료 가능한 크기인가?
- 독립적 실행 가능한가?
- 성공/실패 판단 기준 있는가?

## 점수 체계
```yaml
A (90-100): MECE 완벽, 즉시 활용 가능
B (80-89): 대부분 충족, 경미한 개선
C (70-79): 기본 충족, 중간 개선 필요
D (60-69): 일부 미충족, 상당한 개선
F (<60): 대부분 미충족, 재작업 필요

필수 통과: ME 위반 0개, CE 누락 0개, 총점 80+
```

## 연계
- 품질 게이트: `logical-think` → `logical-verification` → 통과 후 다음 단계
- 개선 사이클: verification → 수정 → re-verification
- 선행 확인: verification → `logical-tree` 또는 `logical-csv`
