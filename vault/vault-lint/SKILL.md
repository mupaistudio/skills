# 볼트 린트 (무결성 점검)

볼트가 원본과 어긋났거나 스스로 부패했는지 점검한다. **검사 · 리포트가 기본**, 수정은 사용자 확인 후.

## 검사 5종

1. **죽은 포인터** — 각 `docs/<문서>.md` 5절 "원본 위치"의 파일 경로 · 링크가 **실제 존재**하나(로컬 경로는 확인, 외부 주소는 접근 가능 여부를 묻지 않고 표시만). 없으면 옮겨졌거나 지워진 것.
2. **INDEX ↔ docs 정합** — `INDEX.md` 에는 있는데 파일이 없거나, `docs/` 에는 있는데 INDEX 에 없는 문서.
3. **복붙 냄새** — 문서에 코드 블록 · 데이터 · 원문이 **실물로 길게** 들어와 있나(기준: 한 블록 30줄 이상). 볼트엔 포인터만 있어야 한다.
4. **stale** — 1절 최종 수정일이 오래됐거나(기본 6개월) 상태(확정 / 작성 중 / 보류)가 비어 있는 문서.
5. **중복/충돌** — **한 주제 폴더 안에서** 같은 내용을 다루는 문서가 둘 이상.

## 검사 단위 — 한 주제 폴더 안

**중복/충돌 · 정합 검사(②·⑤)는 한 주제(`<topic>/`) 안에서만** 한다. 주제는 독립 단위라 **주제 사이에 같은 자원이 있는 것은 부패가 아니다.** 주제 경계를 넘어 "중복"이라 지적하지 않는다. (①③④ 는 문서 단위라 범위와 무관.)

## 절차

1. 대상 주제를 정한다(전체 점검이어도 주제별로 따로 돈다).
2. 검사 5종을 실행한다 — **읽기만** 한다.
3. **리포트** — 항목 · 위치(파일:줄) · 무엇이 문제 · 권장 조치.
4. 수정이 필요하면 **사용자 확인 후** 고친다(포인터 갱신 · INDEX 정합 · 복붙→포인터 치환). 자동으로 지우거나 덮지 않는다.

## 산출

- 린트 리포트(검사별 발견 · 조치). 확인받은 항목만 수정.

## 원칙

- 린트는 **원본은 한 곳** 원칙을 지키는 파수꾼이다 — 어긋남을 드러내되, 되돌리기 어려운 수정은 사람에게 묻는다.
